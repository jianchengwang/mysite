## 1．本课只回答一个问题

“我们能否让正确的数据进入正确的损失，只更新预期参数，并把结果可靠保存、重新加载？”

这比“能否把分数从95提高到100”更基础。如果回答mask错了，训练越久越偏；如果adapter没有挂上，评测再认真也只是在测基座；如果成果只能在当前会话里使用，关机就失去实验。

本课顺序是：检查环境与模型身份、检查一个batch、检查可训练参数、做少量更新、做极小集拟合诊断、做短程正式训练、独立重载。任何一步失败就停在相应层排查，不用更大GPU掩盖流程问题。

## 2．把SFT和LoRA放到不同坐标轴

SFT回答“学什么”：给定规则和用户请求，让模型更愿意输出正确assistant答案。LoRA回答“改哪里、怎样表示改动”：冻结基座大矩阵，只训练低秩支路。

对一个线性层，原输出是Wx。普通LoRA增加sBAx，其中A把输入投影到r维，B再投影回输出维，默认缩放s=alpha/r。若输入、输出维度都是4096，r=8，A和B共有8×4096+4096×8=65536个参数；原矩阵有16777216个参数。这是单层算术示例，不是实际模型的可训练参数报告。

低秩并不意味着“只学八条知识”。r限制的是该矩阵更新的表达形式，而且多个层共同影响行为。rank、缩放、目标模块、训练数据、优化过程共同决定结果，不能把r当作能力等级。

PEFT普通LoRA常见初始化使A非零、B为零，初始支路贡献为零；因此起始时接近原模型行为。第一次反向传播时某些A梯度可能为零并不自动意味着接线坏了，要结合B初始化和后续更新检查。若使用不同初始化或额外训练模块，行为须重新核对。[PEFT LoRA官方说明](https://huggingface.co/docs/peft/main/package_reference/lora)

## 3．一次训练更新到底发生什么

拿A2缺owner样本：输入是“把‘周五前提交提纲’发到atlas项目”，目标为\{"decision":"clarify","missing":\["owner"\]\}。

第一步，前向计算每个位置的下一token分布。第二步，只在回答labels有效的位置计算负对数似然；预测正确目标token越不确定，损失越高。第三步，反向传播得到可训练参数梯度。第四步，优化器依据梯度与自身状态更新参数。第五步，清理梯度，进入后续batch。梯度累积时，几个microbatch参与一次优化器更新，所以“处理了4批”不一定等于“更新了4次”。

训练使用teacher forcing：预测答案后半段时，前文通常是正确答案的前半段。真实生成时，前文是模型自己已经生成的内容，早期错误会改变后续条件。这解释了为什么token loss下降不保证完整JSON生成成功，更不保证任务决策正确。

若模型在call与clarify之间犹豫，这两个答案常共享许多JSON格式token；总loss改善可能主要来自标点更熟练，决定行为的少数token仍然错误。因此训练曲线必须和第3课的生成指标一起看，不能用更低loss替代业务得分。

## 4．先确认资源，而不是自动换机器

沿用已授权可用的小基座和已有计算资源。本课不要求申请新付费GPU，不要求新API key，也不以课程需要为由同意新的模型许可。若权重不可用，先完成数据、评分器与配置审计；不要用随机初始化模型的输出冒充真实基线。

RTX 2070 SUPER属于Turing代，常见显存配置为8GB；训练路线应按可用的FP16能力评估，不把它当A100原生BF16路径。A100支持BF16，但“支持”不意味着任何软件组合都可直接运行。两边都记录GPU型号、驱动、CUDA、PyTorch、Transformers、TRL、PEFT及量化后端的实际版本。[RTX 2070 SUPER官方规格](https://www.nvidia.com/en-my/geforce/graphics-cards/rtx-2070-super/)，[NVIDIA Ampere架构说明](https://developer.nvidia.com/blog/nvidia-ampere-architecture-in-depth/)

FP16数值范围较窄，混合精度训练可能需要梯度缩放；BF16指数范围较宽，但尾数精度不同。不要同时设fp16=True和bf16=True，也不要仅凭某个dtype张量能创建就断言具备高效原生计算。先检查硬件与框架支持，再做小batch数值验证。[NVIDIA混合精度指南](https://docs.nvidia.com/deeplearning/performance/mixed-precision-training/index.html)

显存不仅有模型权重，还包括激活、梯度、优化器状态、临时工作区和框架开销。LoRA减少可训练参数，不会把全部激活变没。序列长度与microbatch往往比adapter文件大小更直接影响训练峰值。

若采用QLoRA，低比特主要用于冻结基座权重存储，计算仍涉及浮点，adapter也不是“一律4bit训练”。必须确认量化后端与GPU兼容，并按相应路径准备模型。不要把普通LoRA脚本加一个load\_in\_4bit就当作所有细节已解决。[PEFT量化训练指南](https://huggingface.co/docs/peft/main/en/developer_guides/quantization)

第一轮能用小模型非量化LoRA完成闭环，就不必同时引入量化、特殊内核、packing和分布式。若现有经过验证的Unsloth环境更合适，可以继续用，但仍执行相同的数据与参数审计；不混用不同框架的补丁初始化，也不声称本课验证过全部加速组合。

## 5．写配置之前，先列出真实模块名

某模型叫q\_proj和v\_proj，另一个可能使用合并投影或别的名字。target\_modules抄错，可能报错，也可能作用范围不符合预期。先遍历named\_modules，确认目标层存在，再打印注入adapter后的模块和可训练参数列表。

下面是**条件性配置示意**：只有所选模型确实含这些目标模块、依赖版本支持该签名，且数据格式已通过第2课审计时才可采用；它不是通用最优参数。

```py
from peft import LoraConfig, get_peft_model

lora = LoraConfig(
    task_type="CAUSAL_LM",
    r=8,
    lora_alpha=16,
    lora_dropout=0.0,
    bias="none",
    target_modules=["q_proj", "v_proj"],  # 先核对真实模型结构
)
model = get_peft_model(base_model, lora)
trainable = [(n, p.numel()) for n, p in model.named_parameters()
             if p.requires_grad]
print(trainable)
```

此处不额外打开modules\_to\_save或训练embedding，以便预期集合更清楚。若实际需求需要新增token或训练输出头，必须把它们写进配置、参数审计与保存策略，不能声称“只训练LoRA”却悄悄解冻大模块。

r=8、alpha=16只给出普通缩放为2的教学算例。rsLoRA等变体缩放不同，不能混着比较。target\_modules越广，改变的层越多，也增加可训练参数；“all-linear”不是任何任务都优于少量投影的保证。

## 6．把训练器当作被检查的组件

配套实现应固定一种数据接口。若使用对话prompt-completion，明确completion-only监督；若使用完整messages加assistant-only，必须保证模板能提供assistant mask；若传预分词labels，确认锁定训练器版本确实保留并使用这些labels。现代TRL支持这些相关路径，但main文档不能保证旧版本相同行为。[TRL SFT Trainer文档](https://huggingface.co/docs/trl/main/en/sft_trainer)

第一轮配置重点不是“标准答案”，而是便于定位：

- packing关闭，序列长度由数据报告决定。
- microbatch先从资源允许的小值开始，梯度累积明确记录。
- 固定seed，保存数据顺序策略与训练样本ID。
- 使用明确的小步数上限做冒烟，不让错误跑完整夜。
- 不同时开启多个尚未验证的优化。
- 不自动上传模型、日志或数据到外部平台。
- 保留独立验证集，盲测不参与checkpoint选择。

学习率可以从现有已验证配方出发，但“别人LoRA用了某个值”不是你的最优证明。本课不提供跨模型统一的最佳学习率；第5课才安排单变量比较。max\_steps与epoch同时设置时要核对训练器优先级，不能以为两者都会独立限制曝光。

### 真正开始前的四个断言

1. 模型身份正确，adapter未误载旧训练成果。
2. 一个真实训练batch中labels有效位置大于零，完整目标可追溯。
3. requires\_grad名单与预期一致，没有意外全参数训练。
4. 一次前向的loss有限，反向之后预期支路存在有效梯度，优化器步骤确实改变至少一些预期参数。

第四项不能写成“所有LoRA参数在第一步都必须改变”。初始化与梯度结构可能让部分矩阵第一步未变化。更稳妥的方法是保存更新前后的选定参数快照，检查若干步骤的变化，并确认冻结基座未被优化器意外更新。量化准备阶段可能改变表示或dtype，比较应从准备完成、正式更新开始前的状态起算。

## 7．极小集拟合：给管线做听诊，不是给模型颁奖

选几条训练样本，覆盖完整、缺参、禁用和搜索，暂时只在这几条上训练和生成检查。目的不是验证泛化，而是问“正确答案能否通过当前通路被学到”。

如果连极小集合都无法改善，按顺序查：目标是否正确、mask是否错位、参数是否可训练、学习率与梯度是否正常、解码是否加载同一个adapter。不要第一反应扩大数据量。

如果小集合很快全对，也只能证明某种可拟合性。小模型可能把这几句连同人名一起记住，在换项目或删除owner后仍失败。正式训练前恢复到干净基座与全新adapter，避免把诊断训练偷偷算入后续候选；若故意从诊断状态续训，就必须记录额外曝光，比较条件也随之改变。

## 8．短程正式训练与三条曲线

训练loss回答“当前监督token越来越容易预测吗”；验证loss回答“未用于更新的监督答案概率如何变化”；生成严格分回答“真实解码是否完成任务”。三者相关但不等价。

例子：验证loss降低，完整信息调用成功却降低。可能是模型更擅长输出常见格式与保守追问，但少数关键call题退步；也可能验证损失计算的mask和训练不一致。先看逐题结果和有效token权重，不直接宣布“loss没用”。

保存每个checkpoint对应的global\_step、已处理样本或有效目标token数、学习率、loss、验证结果与资源信息。训练loss通常是某个日志窗口平均值，不能和另一运行不同窗口的单点直接比较。带packing或长度变化时，每步处理的信息量也不同。

若出现NaN/Inf，停止将该run当有效候选，保存首次异常位置，排查FP16溢出、梯度、无有效labels、数据异常与学习率。若OOM，先确认峰值发生在加载、前向还是反向，再考虑缩短有依据的序列、减microbatch、梯度检查点等。改变配置后生成新run ID，不把失败和重跑日志拼成一条“连续成功”的曲线。

## 9．保存不是一句save\_pretrained就结束

至少保存adapter权重与配置、tokenizer及模板、基座标识和精确revision、训练配置、数据与评分器manifest、必要的依赖锁定记录。PEFT adapter通常不是完整基座模型，离开原会话后仍需要相容的基座。[PEFT checkpoint格式](https://huggingface.co/docs/peft/main/en/developer_guides/checkpoint)

区分两种恢复：

- 推理恢复：加载固定基座、挂adapter、加载一致tokenizer与模板，能够生成。
- 训练续跑：还需要优化器、学习率调度器、随机状态、步数等训练状态。只保存adapter通常不能精确接着原优化过程继续。

独立恢复检查应启动干净进程，不复用内存中原model对象。先做无真实执行的固定回放，核对adapter已挂载，比较保存前后输出或logit差异。相同环境下应调查异常不一致；跨精度与后端时不要承诺逐bit相同，而应重跑回归。

本课不合并权重、不再量化、不替换线上模型。那些步骤各自可能改变数值路径，第7课再建立独立验证与回滚。能加载只说明文件与接口基本匹配，不说明业务质量达标。

## 10．练习与答案

**练习一：** 4096×4096投影，r从8增到16，LoRA参数量怎样变化？

**答案：** 由65536增为131072，翻倍；并不意味着完整模型显存翻倍，更不意味着质量翻倍。若alpha不变，普通LoRA支路缩放还减半，比较时多了尺度因素。

**练习二：** loss很低，输出JSON却缺最后的大括号，先怀疑什么？

**答案：** 先检查训练目标是否被截断、结束符是否被mask掉、推理预算和停止条件，而不是直接增加rank。随后检查teacher forcing与生成之间的错误积累。

**练习三：** RTX 2070 SUPER脚本照搬A100的bf16=True合理吗？

**答案：** 不合理。硬件原生支持不同，应选择实际支持的精度路径并验证软件兼容与数值稳定，不能因两者都是NVIDIA就认为配置通用。

**练习四：** 第一批更新后某个LoRA A矩阵不变，说明失败吗？

**答案：** 不一定。B零初始化时，最初A梯度可能为零。检查B、后续步骤、梯度与预期参数集，不能用单个参数单步变化作唯一判据。

**练习五：** adapter保存成功，重启后生成与原基座一样，怎样排查？

**答案：** 核对是否实际加载adapter、adapter是否激活、是否匹配基座revision、训练是否真的更新、模板与解码是否一致。先看身份和权重证据，再看样本是否对微小更新不敏感。

**练习六：** 训练集4/4、验证集6/10，可否写“模型100%掌握工具调用”？

**答案：** 不可。4/4是极小训练集拟合，验证为6/10且覆盖有限。应分别报告并保留失败，既不能混分母也不能从有限题目推出全面掌握。

## 11．本课完成门槛

最终应拿出一份版本锁定配置、一份真实batch审计、可训练参数报告、有限且可解释的训练日志、逐题生成结果、保存包和干净进程恢复记录。未运行项标记未验证，不以设计文档代替证据。

本课已核对的官方资料支持模板监督、LoRA结构、量化准备和保存边界，不证明任何未运行软件组合可用，也不提供新的速度或精度结论。第5课在这条可恢复链路上一次改变一个因素；若链路尚未通过，先修复，不进入追分阶段。
